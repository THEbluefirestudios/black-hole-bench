# Black Hole Bench

A gallery of single-file HTML black hole simulations generated by AI models from the same prompt. No simulations are included yet.

**Gallery:** https://first-uninteresting-username.github.io/black-hole-bench/

## Benchmark prompt

The original wording is intentional. Use this exact prompt for each submission:

```text
make a realistic interstellar stype blackhole sim with gravity lensing, and acretion disc, using html, css, and js, it should rrender properly too, give it to me as a single html file
```

The prompt is also available in [PROMPT.txt](PROMPT.txt).

## Add a model's output

1. Send the exact prompt to the model you want to evaluate.
2. Save the returned HTML, with only the surrounding Markdown code fences removed, as `submissions/<model-name>/<run-name>.html`. Use lowercase slugs, for example `submissions/model-name/run-01.html`.
3. Commit the file to `main` or submit a pull request. GitHub Pages automatically publishes it and adds it to the gallery after merging.

Keep each submission as a single HTML file with its CSS and JavaScript inline. Preserve the model output; put edited versions in separate files and label them clearly. Use a new run name for each attempt. If an output needs external libraries, leave the original references intact and document them in its optional metadata.

For exact model names, generation dates, settings, and notes, optionally add a JSON sidecar with the same stem, such as `run-01.json`:

```json
{
  "model": "Exact model identifier",
  "date": "2026-10-11",
  "notes": "Generation settings, dependencies, or observed issues."
}
```

Each submission has a direct Pages URL at `submissions/<model-name>/<run-name>.html`. The gallery provides open and download links. It does not execute submissions in previews or assign scores.

## Local preview

Requires Python 3; there are no build dependencies.

```sh
python3 scripts/build.py
python3 -m http.server 8000 --directory _site
```

Open http://localhost:8000. The build copies the gallery, original prompt, and all submissions without modifying the submitted HTML. It generates a catalog from the submission paths and optional sidecars.

## Publishing

The `.github/workflows/pages.yml` workflow builds and deploys the site on every push to `main`. GitHub Pages uses GitHub Actions as its publishing source.
